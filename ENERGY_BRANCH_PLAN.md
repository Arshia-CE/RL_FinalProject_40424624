## 1. Project in one paragraph

University RL final project (spec: `پروژه نهایی.pdf`, Persian, in repo root,
git-ignored). Student ID 40424624 → base_seed 2 → 17×17 seeded maze. Mission:
start (0,1) → key (12,10) → locked door (14,13) → goal (16,16), stochastic
moves (0.8 intended / 0.1 each perpendicular; slips into walls bump). Three
from-scratch algorithms (Value Iteration, Q-Learning, SARSA(λ)), a transfer
study (Q-Learning only, 4 scenarios × 2 perturbed target maps), a Tkinter
game GUI ("MazeMario"), 500-episode greedy evaluations at seed 999, training
seeds {7,21,42}, everything reproducible from `experiments/configs/default.json`,
final report is `report.md` (Markdown, not PDF, by user decision).

**Branch landscape**
- `main` — primary design: periodic gate (period 6, open phases {0,1,2}),
  *departure* semantics (entry allowed iff gate open at the moment the move
  is made). 60 unit tests.
- `future_phase` — same gate, *arrival* semantics (`gate_open(next_phase)`);
  fully re-run; its report ends with §13, a retrospective comparing the two
  designs (use it as the template for this branch's retrospective). 61 tests.
- `limited_energy` (this branch, forked from `main`) — **replace the gate
  with an observable energy budget**. One dynamic feature per branch.

## 3. Energy design (decisions already made — do not re-litigate)

Replace the gate entirely. New state: **`State = (r, c, has_key, energy)`**,
energy ∈ {0..E0}, `E0 = 100` initial (config; tuned in step E.2).
State count 233 × 2 × 101 ≈ **47k** (~17× current — VI fine, learners need
bigger budgets).

Dynamics:
- Every step costs **1 energy** (bumps included — a wasted step still burns
  fuel).
- Entering a penalty cell drains an **extra `penalty_drain` = 5** (config).
  This is what creates the desperation trade-off: pits threaten survival,
  not just reward.
- **energy == 0 ⇒ terminated (death)**, new event `EV_ENERGY_OUT`, reward
  `energy_death = −50` (config; rationale: death must cost more than any
  plausible continued struggle so "give up quickly" is never optimal —
  document this reasoning in the report and sanity-check it in E.2).
- Goal still terminates (success). Step cap 699 stays for spec compliance
  but never binds (energy exhausts first) — note this in the report; the
  `timeout` event may simply never fire.
- The `T` cell becomes plain floor; `gate_blocked` event/reward and
  `gate_open`/phase logic are removed from the env (maps and maze_map.py
  untouched — maps stay byte-identical, transfer targets included).
- Shaping Φ stays the distance-based potential (energy-blind), **but
  `_phi` must return 0 for ANY terminal state — goal AND energy-0** (the
  telescoped sum then gives every trajectory the same −Φ(s₀) offset, so
  Ng-invariance still holds; the report gets to analyze whether an
  energy-blind potential helps less — a feature, not a bug).
- `transitions()` must stay built from `_resolve` and handle the new
  terminal set (`is_terminal` = goal cell OR energy 0 → no outgoing
  transitions).
- History columns: replace `gate_blocked` with `energy_left` (at episode
  end) and `death` (0/1); keep all other columns.

Config: new `"energy": {"initial": 100, "penalty_drain": 5,
"death_reward": -50}`; learner budgets up: q_learning/sarsa/transfer
`episodes` ≈ 15000–20000, `epsilon_decay_episodes` ≈ 12000, trace episodes
rescaled; expect the full pipeline to take **several hours — run overnight
in the background**. Trimming levers if needed: E0 = 80, or fewer sarsa λ
seeds — but the spec requires all 4 λ values and 3 seeds, so prefer
patience over trimming.

Validation gates (do these BEFORE burning training compute, in E.2):
1. VI solves; optimal success ≈ 97–99% (an irreducible death rate under
   slips is expected and is a headline phenomenon — if it's 100%, lower E0;
   if below ~95%, raise it).
2. **The desperation flip exists**: find states where π*(same cell, same
   key, high energy) detours around a pit but π*(low energy) cuts through
   it. Search over pit-adjacent cells comparing policies at energy bands.
   If absent, raise `penalty_drain` (5 → 8) or tighten E0 until it appears.
3. Transition probs sum to 1 over all ~47k × 4 pairs (existing test
   pattern).

## 5. Gotchas learned the hard way

- `QLearningAgent.load_table` and `VIResult.load` need `Path` objects, and
  `load_table` returns `(table, meta)` — unpacking mistakes silently
  produce a wall-bumping agent.
- The experiment console prints show the LAST seed; report tables use seed
  means from the CSVs.
- `write_csv` unions keys across rows — new history columns appear
  automatically, no writer changes needed.
- Regenerated PNGs/models that are byte-identical don't show in
  `git status` — that's the determinism check working, not a bug.
- Matplotlib runs headless (`Agg` set in analysis.py). Tk smoke tests use
  `root = tk.Tk(); root.withdraw()`.
- Comparison figures/CSVs retrain QL+SARSA in-process (~1–2 min now, more
  with bigger budgets) — it does NOT load the saved models for training
  stats, only for file sizes.
- The GUI loads Q-tables from `MODEL_FILES` fixed paths; retraining
  regenerates them in place, WATCH mode then reflects new dynamics
  automatically.
